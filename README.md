Falsely Altered Mathematical Evaluation (FAME) is a benchmark designed to evaluate LLMs’ ability to evaluate mathematical edits in multi-hop reasoning processes, allowing us to analyze how a single or multiple points of misinformation can affect the model’s performance. Problems in this benchmark can be one of two kinds: evaluating an expression or the value of an unknown variable in an equation.

To use this benchmark, do the following:
 - Download the benchmark csv from this github repository, and open an IDE with access to this benchmark.
 - Loop through each of the rows in the csv
    - For each row, ask the model to generate an answer to the question in the 'problem' row with the false math facts from the 'facts' row in mind (example prompts given).
    - Answers are correct if the answer generated by the model is the same as the answer in the 'edit' column
    - Answer are incorrect, but true without the false math facts in mind (real arithmetic), if the answer given by the model matches the answer given in the 'real' column.
 - Find the accuracy of the model using these rules to find out the model's performance with FAME

How the benchmark was generated:
We begin by selecting a base set of incorrect arithmetic equations using the operations of PEMDAS. For example, "2 + 2 = 5," "3 / 3 = 2," and "2 ** 3 = 10" (** meaning exponents). Every fact that is required for a problem is then added to a list which will be directly prompt-fed to models, altering their original adherence to conventional math.
For the two different kinds of problems, expression-evaluation and algebra problem-solving, the same amount of base false facts are initialized. For problems involving evaluating the value of a single expression, a random number of one to three false facts can be initialized for the problem. For problems involving algebra, there are two sides to equations; only the left-hand side is initialized with base facts, so one to three random facts are generated solely to be added to the left-hand side.
We then generate expressions to evaluate the model’s ability to reason over edited mathematical knowledge. Each equation is transformed by different modifications that make the expression more complicated to evaluate. This method allows for the existence of problems ranging from minimal problem-solving to precise calculations and accuracy. As seen in Figure \ref{fig:branching_tree}, transformations for problems can be one of the following three: (1) one of the four basic operations and a number is added to the expression, encasing the previous expression in parentheses; (2) a two-number expression using one of the four basic operations is inserted into the existing expression replacing a previous number which had the same value; and (3) a false mathematical fact is inserted into the existing expression, and the new fact is added to the list of false facts to be prompted to the model.
For expression-evaluation, a random number of one to three transformations will be added to each problem. For algebra problem-solving, like expression-evaluation, a random number of one to three transformations will be added to the left-hand side of the equation, and the right side will have one to five transformations. 
Difficulty is counted by summing up the number of operators in the expression or equation. For expression-evaluation, the difficulty ranges from 2 to 8. For algebra problem-solving, the difficulty ranges from 3 to 11. The variety of randomly generated equations allows us to vary both the depth and difficulty of problems, allowing metrics to calculate model performance as more and more modifications are added.
